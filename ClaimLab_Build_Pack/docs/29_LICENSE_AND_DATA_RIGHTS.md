# Licenses, Attribution, and Data Rights

## Scope

Track the rights associated with code, models, documents, images, datasets, and demo material. This is an engineering record to complete with actual dependencies and assets; it does not certify legal compliance or select a binding license on Ravi's behalf.

## Project source

A public repository is required by the supplied guide, but public visibility alone does not grant an open-source license. Before publishing, Ravi should choose an appropriate project license and include its actual text. MIT is a possible simple software choice, subject to the actual included code and dependencies; this pack does not declare that choice already made.

Record code brought from an earlier repository, third-party snippets, generated assets, and contributions. Preserve license notices and clearly identify event-period changes. Do not attribute all pre-existing libraries to the hackathon build.

## Dependency record

During bootstrap, record each resolved package/version, its license, upstream URL, required notices, and whether it is redistributed. Include frontend packages, backend packages, container base images, fonts, and PDF rendering assets. Verify the actual version's license rather than assuming one from a package name.

## Models and services

Record the actual Meta model, serving mode/provider, applicable model/service terms, and date verified. Hosted and open-weight use can have different obligations. No open-weight bonus eligibility is established by using the hosted model alone; verify actual model/serving requirements before claiming an award category.

## Student material

Uploading a document for private learning does not grant permission to publish it in a repository or demo gallery. Keep raw uploads and individual learning records private. For a public demonstration, use the author-created note in [reference lessons](27_REFERENCE_LESSONS.md) or material with appropriate permission and attribution.

Do not copy whole books or papers into public fixtures just because they are downloadable. Link to original sources where redistribution rights are unclear. Derived diagrams should cite relevant sources and avoid misrepresenting original figures as new research.

## Supplied participant guide

[The guide snapshot](../references/PARTICIPANT_GUIDE_SUPPLIED.md) is included as a private handoff input supplied by Ravi. It is not automatically a project-owned public asset. Before pushing this documentation pack into a public repository, remove that snapshot unless redistribution permission has been established; retain links and the operational rules summary instead.

## Attribution record to maintain

For each distributed asset, record name, source, author, version/date, license/permission, modifications, and where the notice appears. If none are redistributed, state that actual condition rather than inventing a list.

## Demo claims

Attribute the paper motivating an experiment. Identify synthetic inputs and illustrative scope. Do not present someone else's benchmark result as ClaimLab's measured performance or a staged student demonstration as a real learning study.
