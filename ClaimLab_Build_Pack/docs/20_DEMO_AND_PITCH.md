# Demo and Pitch

## One-sentence description

ClaimLab turns supported technical papers into adaptive whiteboard lessons and executable experiments, using student predictions and actions to choose what to teach next.

## The story to prove

A difficult idea becomes a visible model, a testable intervention, an actual result, and a new application. A deliberate student mistake changes the next lesson. The evidence panel shows why the system acted and what ran.

This is a proposed recording structure, not a claim that these features already work.

## Three-minute structure

| Time | What is shown | What it establishes |
| --- | --- | --- |
| 0:00–0:15 | State the problem and supported audience | Clear real-world purpose |
| 0:15–0:35 | Upload/select a relevant passage and ask a question | Material-specific learning goal and source grounding |
| 0:35–1:05 | Agent draws the relevant mechanism and asks a prediction | Actual teaching actions and student participation |
| 1:05–1:40 | Run the selected experiment; change an input and inspect results | Tool use, actual computation, and traceable visuals |
| 1:40–2:15 | Deliberately submit a conceptual mistake; show the changed explanation | Observable adaptation rather than a fixed lecture |
| 2:15–2:40 | Complete a different application; show assistance record | Evidence about understanding, without a mastery guarantee |
| 2:40–3:00 | Show source/run/decision evidence and state scope limits | Engineering credibility and honest claims |

Total: 180 seconds. Account for loading/editing so the exported file meets the organizer's actual video requirement. If a transition is sped up or a run was recorded earlier, disclose it accurately.

## Narration principles

Say “we deliberately make this mistake to demonstrate adaptation” when the presenter is acting as the learner. That is a valid product demonstration, not evidence of an actual participant's learning gain.

Use a concise explanation of the live Meta role: it interprets the source and student evidence, chooses supported tools, and changes the lesson. Reviewed numerical code produces the result; the model interprets it with source and assumption boundaries.

## Suggested opening

“Reading a paper does not always tell you whether you understand its mechanism. ClaimLab lets you see an idea, predict its behavior, test it, and try a new application. The teacher changes its approach using your work.”

## Suggested closing

“This version supports a focused attention lab. Every chart comes from a recorded calculation, and every teaching change links to student evidence. Our next research question is how much this improves independent understanding across more learners and methods.”

Use this wording only if those statements are true of the actual release. Report any unimplemented part honestly.

## Evidence to have available

The exact deployed commit; actual model mode/ID; supported source anchors; run/check records; teaching decision/evidence IDs; held-out supported input result; known limits; and third-party attribution. Keep keys and private learner data out of the recording.

## Judge questions to prepare for

- What actually runs, and how do you know the result is correct?
- Which student evidence changes the next action?
- How is a source statement distinguished from an assumption?
- How does the system handle unrelated material or an invalid equation?
- What is substantive about the Meta integration?
- What was built during the event?
- What learning effectiveness has actually been measured?

Answer from evidence. Do not describe planned voice features, universal paper support, or future research as current capabilities.
