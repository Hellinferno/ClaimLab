# Definition of Done

## Documentation pack

The pack is complete when the agreed idea is preserved, every requested area has a substantive document, contracts are internally consistent, relative links resolve, schedules/timezones agree, and the archive contains the intended Markdown files. That establishes documentation readiness only.

## Individual implementation task

- The actual behavior matches its requirement and area-specific contract.
- Input validation, failure states, ownership, and state updates are implemented where relevant.
- Appropriate meaningful tests/checks pass.
- The UI represents the backend truth.
- No secrets/private content were introduced into tracked files.
- A material decision or changed limit is reflected in documentation.
- Status records the implementation and verification evidence accurately.

## Milestone

Its dependency prerequisites and exit criteria in [the implementation plan](15_IMPLEMENTATION_PLAN.md) are satisfied. A screenshot alone does not establish a working backend; a passing unit test alone does not establish a working browser journey.

## Supported learning loop

The student can upload/select a relevant source, see grounded teaching, participate semantically, run an actual checked experiment, receive a relevant adaptation, and attempt a different application. The same session can resume correctly. A second owner remains isolated.

## First-release readiness

Every P0 acceptance criterion has implementation evidence. All critical numerical, source, ownership, execution, deletion, and job-state checks pass. Live Meta compatibility and adaptation have been verified on the release configuration. The hosted environment has actual isolation, budgets, TLS, and retention behavior.

Unsupported topics and unmeasured learning claims are stated plainly. Fixture mode is distinguishable. Public code/material rights are checked. The exact submitted version can be reproduced.

## Demo readiness

The three-minute recording shows actual capabilities and identifies staged/recorded segments. The video and required product links are accessible to reviewers. No private data or keys appear. Claims match the release, and the demonstrated mistake/adaptation is clearly distinguishable from a measured learning study.

## Submission complete

The portal has returned actual success confirmation for the authorized submission. Retain the submitted commit, links, representative, and confirmation. A prepared form or uploaded video alone is not a submitted project.

## Evidence vocabulary

Use **planned**, **implemented**, **verified offline**, **verified live**, **deployed and verified**, and **submitted** according to actual events. Do not collapse these into a single unchecked “done” label.
