## 1. Latency and throughput: where a tutor turn spends time in our own code, and what moving turns to background jobs and streaming would take

### Takeaway
Our own code adds little to a turn. DB work is about 30–50 small SQLite statements and roughly 10–15 commits, which is milliseconds. Latency comes from **sequential provider round trips**, up to 7 per turn, each re-sending about 25k+ characters of prompt. The tool calls inside one reply also run one after another. The structural fix is to run turns as background jobs with progress events. The pieces exist (Job/JobEvent tables, `worker.py`, an SSE route), but the worker and the SSE route are both broken today (verified), and the frontend has no job client. True lesson streaming also needs provider `stream: true` with tool-call deltas, which is unverified for muse-spark-1.3.

**Throughput / blocking**
- The tutor routes are `def` (synchronous) and run the whole turn inside the request: `create_learning_session` → `execute_tutor_job` ([api:795-800](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), `submit_learner_event` → `execute_tutor_job` ([api:978-979](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), and `POST /runs` with a sandbox re-run ([api:1024-1043](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). docs/07 itself flags "the current tutor and recipe routes still execute synchronously before returning their 202" — [docs/07:49](file:///D:/Meta%20hackathon/docs/07_API_CONTRACTS.md).
- Starlette runs `def` endpoints, and FastAPI's sync dependencies, in an AnyIO thread pool whose **default is 40 tokens**, shared by every sync route and dependency — [Starlette thread pool docs](https://www.starlette.io/threadpool); [AnyIO threads docs](https://anyio.readthedocs.io/en/latest/threads.html). `get_db` and `get_current_guest` are sync dependencies ([database.py:35-40](file:///D:/Meta%20hackathon/backend/src/claimlab/database.py); [security.py:50-81](file:///D:/Meta%20hackathon/backend/src/claimlab/security.py)). `/health/live` is also `def` ([api:288-290](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- nginx's default `proxy_read_timeout` is 60 s between two successive reads, and the connection closes if the upstream sends nothing in that window — [nginx ngx_http_proxy_module](https://nginx.org/en/docs/http/ngx_http_proxy_module.html). A synchronous turn sends no bytes until it finishes. First turns with web research took 43–90 s ([docs/25 addendum 30 Oct](file:///D:/Meta%20hackathon/docs/25_STATUS_AND_HANDOFF.md)).
- The browser `request()` has no timeout or AbortController — [App.tsx:10-19](file:///D:/Meta%20hackathon/frontend/src/App.tsx) (grep found no `AbortController` in `frontend/src`).

**State of the background-job pieces (verified broken)**
- `worker.execute_job` opens a **new** `SessionLocal()` and then calls `db.refresh(job)` on a `Job` loaded by the loop's session — [worker.py:37-45, 64, 112](file:///D:/Meta%20hackathon/backend/src/claimlab/worker.py). The probe reproduced `InvalidRequestError: Instance '<Job …>' is not persistent within this Session`. So every claimed job fails before it runs. The error handler then raises the same error again (line 64), and the job stays RUNNING until its lease sweep (inferred from code plus the probe).
- The worker lease is 30 s and nothing renews it: `HEARTBEAT_INTERVAL_SECONDS` is defined but never used ([worker.py:15-16](file:///D:/Meta%20hackathon/backend/src/claimlab/worker.py); grep shows no other use). Live turns take 17–46 s or more. An API process would mark a still-running worker job `WORKER_LOST` once 30 s pass ([api:241-250](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- The only worker test covers claiming and stale-lease recovery, and never runs `execute_job` on a real job — [test_complete_spec.py:345-390](file:///D:/Meta%20hackathon/backend/tests/test_complete_spec.py).
- The SSE route uses the request's `db` dependency inside a `StreamingResponse` generator ([api:1118-1152](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). On the installed FastAPI 0.115.4 the probe logged `['dep-open', 'dep-closed', 'body-start', 'body-end']`: the dependency closes **before** the stream body runs. The planned event types (`run_started`, `run_completed`, `board_updated`, …) are listed there. The orchestrator currently emits only `tutor_turn_completed` and the private `task_key_recorded` ([orch:1109-1135](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)).
- The probe script reads `usage.prompt_tokens/completion_tokens` from the Meta response ([probe_meta_api.py:72, 83-84](file:///D:/Meta%20hackathon/backend/src/claimlab/scripts/probe_meta_api.py)), so token counts are available. The orchestrator ignores them.

### Inferences
- **DB is not the bottleneck.** About 50 small statements and 10–15 WAL commits cost tens of ms per turn at most, under 1% of a 17–46 s turn. `PRAGMA synchronous=NORMAL` (safe in WAL) and removing the duplicate runs query are hygiene, not latency wins (inferred; not profiled).
- **Prompt size per call:** with 3.2k chars of system prompt, 2.3–6.1k of tools, ≤14k of source, and 3–5k of board, runs, and evidence, each call carries roughly 22–28k chars before tool results. At about 4 chars/token (a heuristic, not measured) that is 6–7k input tokens. A 6-call turn re-sends it 6 times plus growing tool results, so cumulative input is about 40–70k tokens per turn. Prefill time and cost scale with this.
- **Latency levers in our code, from most to least promising (all inferred, unmeasured):**
  1. *Fewer round trips.* Cap first-turn web research at one search plus one read. Tell the model to issue experiments and web calls together in one reply (the prompt already asks this, [orch:75](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). Count `get_source_excerpt` as non-blocking.
  2. *Run the tool calls of one reply concurrently* with a `ThreadPoolExecutor` (sandbox subprocesses and TinyFish HTTP are I/O-bound). Keep DB writes on the request thread. Wall time drops from the sum of the tools to the slowest one. Effort S–M.
  3. *Trim feedback-turn context.* On answer and hint turns, send only the anchors the previous turn cited (`step.anchor_id`, quote `source_refs`) plus the run digests, not all 14k chars.
  4. *Shrink `run_experiment` tool results* to a digest like `tool_summary`, instead of the full `output`.
  5. *Reuse one module-level `httpx.Client`* each for Meta and TinyFish, which saves a TCP+TLS handshake per call (tens to hundreds of ms each).
  6. Keep the stable prefix (system prompt, tool specs, passage) byte-identical across calls so that any provider-side prefix caching can apply. Whether Meta caches prefixes is unknown.
- **Throughput ceiling:** each in-flight live turn holds one of the 40 AnyIO tokens for the whole turn. Inferred: about 40 concurrent learners would stall *every* sync route, including `GET /learning-sessions/{id}` and `/health/live`. A hackathon demo will not hit this; a shared deployment could.
- **What background jobs would take (design sketch, effort M for the core and L with streaming):**
  1. The `POST /learning-sessions` and `POST /events` routes insert the LearnerEvent and a `Job(status=QUEUED)`, set `session.active_job_id`, and return 202 at once with `tutor_job_id`. The response shape already matches docs/07.
  2. Execution: either (a) an in-process `ThreadPoolExecutor(max_workers=2–4)` started in a FastAPI lifespan hook, which fits D-06's single instance with no new process, or (b) a fixed `worker.py`: re-query `Job` by id inside `execute_job`, renew the lease from a checkpoint callback, and set the lease ≥ the turn's worst case. Option (a) is simplest. Option (b) survives API restarts, which D-06 calls "durable".
  3. Pass the orchestrator a `progress(event_type, data)` callback that writes JobEvents (`tool_started{name}`, `run_completed{run_id, summary}`, `web_read{host}`, `lesson_committed`, `tutor_turn_completed`) and checks `job.cancelled` and the fencing generation between iterations. That makes cancellation cooperative (see Section 2).
  4. Fix SSE by opening a short-lived `SessionLocal()` per poll inside the generator, via `run_in_threadpool`. Upgrading to FastAPI ≥0.118 instead would hold one session for the whole stream. Send a `: keep-alive` comment every ~15 s, which keeps proxies such as nginx (60 s between reads) open. Honour `Last-Event-ID`.
  5. Frontend: after the 202, open `EventSource('/api/v1/jobs/{id}/events')` (GET with the same-origin cookie; no CSRF header needed). Map events to stage text ("Running your experiment…", "Reading en.wikipedia.org…", "Drawing the lesson…"). Call `refreshSession` on `tutor_turn_completed`. Fall back to polling `GET /jobs/{id}` every 2 s, as docs/07:134 specifies.
  6. Tests: queue → execute → events → session state; cancel mid-turn; delete mid-turn; lease renewal.
- **Streaming the lesson itself.** The only way to show step 1 before the 12–23 s final reply ends is provider streaming (`stream: true`) of the `present_lesson` tool-call argument deltas. We would parse the partial `steps[]` array incrementally and emit a `step_ready` event per completed step object. Without provider streaming, background jobs remove proxy timeouts and blank waits, but **not** the 12–23 s for the first step to appear.

### Gaps
- Whether Meta's OpenAI-compatible endpoint supports `stream: true` with incremental `tool_calls[].function.arguments`, reasoning-effort controls, or prompt-prefix caching. The probe script does not test any of these.
- No per-phase timing exists (prefill vs generation vs tool execution). I found no instrumentation in `orch`. Every latency number in docs/25 is a single observation.
- Sandbox process start-up cost on Windows (interpreter + numpy import) was not measured. `SandboxResult.duration_ms` records it per run ([executor.py:373](file:///D:/Meta%20hackathon/backend/src/claimlab/sandbox/executor.py)), so it could be read from retained runs.

## 2. Reliability: error handling in the tool loop, retries/timeouts, idempotency, leases, partial failures, model-output drift

### Takeaway
Any single provider hiccup fails the whole turn: there is no retry, and on a first turn the lesson is discarded. Cancellation and fencing are recorded but never enforced, so a "cancelled" turn finishes and is marked SUCCEEDED. Deleting data during a turn leaves rows behind and crashes the turn (verified with an SQLAlchemy probe). Smaller holes: TinyFish non-JSON replies crash the turn, the dispatcher executes tools it did not offer, and duplicate tool-call IDs hit a unique constraint. Model-output drift handling in `lesson_builder` is thorough, but one bad item can silently drop a whole 20-command chunk.

### Cited Findings
**Provider calls and timeouts**
- One `try` wraps POST + `raise_for_status` + `.json()`. *Any* exception, including 429/502/503 or a read timeout, releases the budget and raises `ProviderUnavailableError`, with **no retry** — [orch:775-798](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py). `data["choices"][0]["message"]` sits *outside* the try ([orch:800-801](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)), so a malformed 200 body raises KeyError and becomes a generic `SERVICE_NOT_READY` 503 ([api:212-222](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- `httpx.Client(timeout=60.0)` ([orch:770](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). httpx timeouts apply per operation (connect/read/write/pool), and the read timeout is "the maximum duration to wait for a chunk of data"; there is no overall timeout — [httpx timeouts](https://www.python-httpx.org/advanced/timeouts/).
- `finish_reason == "length"` (truncated tool-call JSON) is not detected. Truncated arguments become `fn_args = None` → "Tool arguments must be a JSON object", which costs another full call — [orch:805-817, 833-834](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py).
- A first-turn failure deletes the session and its ExperimentRuns ([api:253-262, 796-800](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). docs/08 asks to "Retain already committed valid checkpoints if the final request fails" ([docs/08:23](file:///D:/Meta%20hackathon/docs/08_AGENT_ORCHESTRATION.md)); that is not implemented.

**Tool loop**
- The dispatcher runs any known tool name, **whether or not it was offered** in that call. On a final call `live_tools(final=True)` offers only `present_lesson`/`assess_answer` ([orch:1284-1286](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)), but `run_python_experiment`, `run_experiment`, and web branches still execute if called ([orch:836-874](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). The same applies on feedback turns with `experiments=False` ([orch:726, 780](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)).
- `ToolInvocation` has `UniqueConstraint(job_id, provider_call_id)` ([models.py:263-275](file:///D:/Meta%20hackathon/backend/src/claimlab/models.py)). The loop inserts without checking first ([orch:821-830](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)), although docs/08 says "Dedupe by `(job_id, provider_tool_call_id)`" ([docs/08:49](file:///D:/Meta%20hackathon/docs/08_AGENT_ORCHESTRATION.md)).
- `_web_tool` catches only `WebResearchError` ([orch:1248-1259](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). `search_web`/`fetch_page` call `response.json()` and `.get()` on the parsed body without guarding against non-JSON or a non-dict body ([web_research.py:60, 91-95](file:///D:/Meta%20hackathon/backend/src/claimlab/services/web_research.py)), so a `ValueError` or `AttributeError` would abort the turn.
- The `run_experiment` branch catches every exception and returns `str(e)` to the model ([orch:856-857](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). This is fine for validation errors but can leak internal messages into the prompt.
- Turn duration vs lease. The lease is 300 s ([api:94](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). After the 60 s deadline every further iteration is a "final" call, but the loop continues while the model keeps replying without `present_lesson` (for example, `assess_answer` alone), up to 7 iterations × ≤60 s read timeout each, plus sandbox (10 s) and fetch (35 s) time ([orch:771-774, 935-936](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)).

**Cancellation, fencing, deletion races**
- `POST /jobs/{id}/cancel` sets `cancelled=True`, sets status CANCELLED, clears `active_job_id`, and bumps `fencing_generation` ([api:1171-1181](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). The orchestrator never reads `cancelled` or the fence; grep finds `.cancelled` only in `api.py` and `worker.py:24,45`. `fencing_generation` is only ever incremented (`api.py:248, 385, 1179`; `worker.py:106`) and never compared. When the turn finishes, `execute_tutor_job` overwrites the status with `SUCCEEDED` ([api:223-227](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- The cancel test cancels an already-succeeded *parse* job and accepts either `"cancelled"` or `"succeeded"` — [test_complete_spec.py:297-317](file:///D:/Meta%20hackathon/backend/tests/test_complete_spec.py).
- `DELETE /me/data` purges all rows and commits ([api:378-429](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)) while a synchronous turn on another thread keeps its `session` object. The probe confirmed SQLAlchemy 2.0.36 raises `StaleDataError: UPDATE statement on table 'jobs' expected to update 1 row(s); 0 were matched` when an object deleted by another session is updated. The turn commits ToolInvocation, ExperimentRun, and BudgetReservation rows *before* its final `session.revision` update ([orch:749-750, 829-830, 848, 865, 925-927](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)).
- `session_is_busy` treats a passed lease as an orphan and releases the lock ([api:230-250](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), but nothing stops the old thread if it is still running.

**Idempotency**
- Route idempotency is recorded only *after* the synchronous turn ([api:742-744 → 807; 910-912 → 990](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). The browser generates a **fresh** `Idempotency-Key` on every call ([App.tsx:53](file:///D:/Meta%20hackathon/frontend/src/App.tsx)), so a retry never reuses a key.
- `IdempotencyRecord.expires_at` is set to 24 h ([api:202](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), but `handle_idempotency` never checks it ([api:148-176](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)) and nothing deletes expired records.

**Model-output drift (lesson_builder)**
- There is broad recovery: text keys, tag keys, draw keys, URL keys, and flattened items ([lb:33-50, 53-83](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)); prose from lists and objects, with title-only fallbacks ([lb:278-286](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)); quote verification ([lb:174-193](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)); and run-bound plots ([lb:389-395](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)). There are 15 open-lesson tests ([test_open_lessons.py](file:///D:/Meta%20hackathon/backend/tests/test_open_lessons.py)).
- `apply_commands` applies 20-command chunks, and "an invalid chunk is skipped". One bad command drops up to 19 valid ones, and connectors in later chunks that point at dropped objects fail too — [lb:206-214](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py) with `MAX_COMMANDS_PER_PATCH = 20` ([whiteboard/engine.py:16](file:///D:/Meta%20hackathon/backend/src/claimlab/whiteboard/engine.py)).
- `_first_number` takes the first number in the text. "1/2" grades as 1, and "50%" grades as 50 against a key of 0.5 — [lb:496-502, 479-487](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py).
- Evidence for the prompt is loaded without `order_by` ([orch:457-461](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)), while the API orders by `created_at` ([api:846-847](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). So "latest category per concept" depends on SQLite scan order in the prompt.

### Inferences
- **Provider retry (S):** retry 429/5xx/connect errors once or twice with jittered backoff, but only while `time.monotonic() < deadline`. Honour `Retry-After`. Move `choices[0]` parsing inside the guarded block and validate its shape. Treat `finish_reason=="length"` as a signal to send "your last call was cut off; send fewer/shorter steps".
- **Partial-failure checkpoint (M):** if the provider fails after a successful run or web read, the turn can still commit a minimal lesson. For example, `paginate_text` of a server-built "Here is what I measured" step from `run_digest`, plus a plot of the run, tagged honestly. Or keep the session on a first-turn failure when a run succeeded, so a retry can reuse the run. This follows docs/08:23 and avoids repeating 10–30 s of work.
- **Enforce the offered-tool set (S):** pass the list from `live_tools(...)` into the dispatcher and answer un-offered names with `{"status":"rejected","error":"not available this turn"}`.
- **Dedupe tool calls (S):** on a `(job_id, provider_call_id)` hit, return the stored `result_reference`; otherwise synthesise a unique id. Without this, a provider that reuses ids such as `call_0` across iterations would make every multi-call turn fail with IntegrityError. Whether muse-spark reuses ids is unverified.
- **Cooperative cancel and fence (S–M):** at each loop iteration and before the final commit, re-read `job.cancelled` and `session.fencing_generation` against the values captured at start. On mismatch, roll back and stop. In `execute_tutor_job`, never overwrite a CANCELLED status. This also fixes the cancel-then-new-event race, where two turns run on one session, both compute `session.revision + 1` from stale state, and the last writer wins (inferred).
- **Delete during turn (M, also a privacy issue; see Section 4):** take a per-owner lock or check, or have the turn check `guest.deleted_at`/the fence before each commit, and have delete wait for or cancel running jobs.
- **Chunk drop:** validate each command individually (the engine already validates per object) and keep the valid ones, or validate per object before chunking.
- **Answer parsing:** support `a/b` fractions and `%`, divide by 100 when the key is ≤1, or reject ambiguous answers with "enter a decimal".

### Gaps
- How often muse-spark-1.3 returns 429/5xx or duplicate tool-call ids. I found no retained provider error logs.
- Real-world frequency of the chunk-drop case. The warnings at [lb:213](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py) go to the log only, and no counts are retained.

## 4. Security and privacy beyond the sandbox: CSRF/cookies, upload limits, PDF parsing, prompt-injection boundaries, retention/deletion

### Takeaway
The CSRF design is sound. The weak spots are elsewhere:
- An **unrestricted `read_web_page` URL**, a prompt-injection exfiltration channel.
- **Unfiltered links in tutor Markdown.**
- **Deleting data during a turn leaves private rows behind.**
- **No expiry sweeper**, and idempotency records never expire.
- **Insecure-by-default config** (APP_ENV defaults to development).
- **Unbounded request fields** that flow into paid prompts, with **no spend cap**.
- **pypdf 5.1.0, which has a known RAM-exhaustion CVE**, parsed in the API process.
- A **sandbox fallback to the app interpreter**.

### Cited Findings
**CSRF/cookies/origin**
- The CSRF token is HMAC-derived from the cookie and checked with `compare_digest`. Mutating routes require the `X-CSRF-Token` header, and the cookie is HttpOnly with SameSite=Lax — [security.py:20-29, 84-112](file:///D:/Meta%20hackathon/backend/src/claimlab/security.py); [api:335-342](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py). CORS uses explicit origins with credentials ([api:122-128](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- `APP_ENV` defaults to `"development"` and `SESSION_SECRET` to a fixed dev string ([config.py:7, 11](file:///D:/Meta%20hackathon/backend/src/claimlab/config.py)). In development the Origin check is skipped ([security.py:95](file:///D:/Meta%20hackathon/backend/src/claimlab/security.py); [api:313](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)) and the cookie is not `Secure` ([api:339](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). Nothing refuses to start with the default secret outside development.

**Prompt-injection boundaries**
- `read_web_page` fetches **any** http(s) URL the model names: `fetch_page(str(args.get("url")))` ([orch:1253](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py); [web_research.py:73-78](file:///D:/Meta%20hackathon/backend/src/claimlab/services/web_research.py)). The allow-list of research URLs (`web_urls`) is applied only to *citations* in the lesson ([lb:255, 295-302](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)), not to fetching. The risk register already names "file read … then sent out in a web_search query" as the chain to watch — [docs/22 risk register](file:///D:/Meta%20hackathon/docs/22_DECISIONS_AND_RISKS.md).
- Tutor prose is rendered with a Markdown subset that turns `[text](https://…)` into clickable `<a target=_blank>` links ([Markdown.tsx:6, 18-19](file:///D:/Meta%20hackathon/frontend/src/components/Markdown.tsx)). The step body is not filtered against web sources ([lb:278-290](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)). No HTML is injected (React elements only).
- Source and web text are labelled as data in the system prompt and in tool results ([orch:63, 82, 1252, 1257](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). Quotes are verified verbatim ([lb:376-387](file:///D:/Meta%20hackathon/backend/src/claimlab/services/lesson_builder.py)).

**Input bounds and spend**
- `CreateSessionRequest.goal` is an unbounded `Optional[str]`. `SubmitLearnerEventRequest.event_type` is a free `str`, and `payload` is an unbounded `Dict[str, Any]` ([contracts/session.py:10-27](file:///D:/Meta%20hackathon/backend/src/claimlab/contracts/session.py)). `session.goal` goes into every prompt untruncated ([orch:1166, 1222](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)). The payload is stored whole ([api:936-962](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). Any `event_type` that is not an answer or hint still triggers a live turn ([api:965-979](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). By contrast, `CreateSelectionRequest.question` is bounded to 3–1000 chars ([contracts/document.py:42-45](file:///D:/Meta%20hackathon/backend/src/claimlab/contracts/document.py)).
- Guest creation is unauthenticated and unlimited ([api:310-346](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). Per-guest quotas are 3 documents and 5 sessions ([api:477-485, 747-755](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), but there is no per-guest turn limit. There is no global budget: `APP_AI_BUDGET_USD` is unused and the reservation amounts are hard-coded (Section 3).

**Uploads and PDF parsing**
- Upload accepts any filename ending in `.pdf` (no `%PDF-` magic check) and reads up to 10 MiB + 1 into memory ([api:447-460](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). `file.filename.lower()` would raise if `filename` were `None`. A parse failure returns `f"Failed to parse PDF: {str(e)}"` to the client ([api:490-496](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)).
- pypdf parses in the API process (FastAPI's thread pool) with no memory or time limit ([pdf_service.py:31-75](file:///D:/Meta%20hackathon/backend/src/claimlab/services/pdf_service.py)). The page-count limit (50) is checked only after `PdfReader` has loaded the document ([pdf_service.py:36-42](file:///D:/Meta%20hackathon/backend/src/claimlab/services/pdf_service.py)). The installed version is **pypdf 5.1.0** ([requirements.lock](file:///D:/Meta%20hackathon/backend/requirements.lock)).
- CVE-2025-55197: "Prior to version 6.0.0, an attacker can craft a PDF which leads to the RAM being exhausted". It is triggered just by reading a file with chained FlateDecode filters in a cross-reference stream, and fixed in 6.0.0 — [Chainguard CVE-2025-55197](https://images.chainguard.dev/security/CVE-2025-55197); [Red Hat bug 2388450](https://bugzilla.redhat.com/show_bug.cgi?id=2388450). A search summary also mentioned CVE-2026-22691 (long runtimes from malformed startxref, patched in 6.6.0); I did not open a primary page for it ([search result list](https://vulnerability.cert.dk/vuln/cve-2025-55197)).

**Sandbox-adjacent (not the OS-isolation item)**
- If `.sandbox-venv` is missing or incomplete, the executor **falls back to the application interpreter and its site-packages** and only logs a warning ([executor.py:112-120, 384-385](file:///D:/Meta%20hackathon/backend/src/claimlab/sandbox/executor.py)).

**Retention and deletion**
- There is no expiry sweeper. `expires_at` is used only for authentication filtering ([security.py:70](file:///D:/Meta%20hackathon/backend/src/claimlab/security.py); [api:327](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)). The worker sweeps job leases, not owners ([worker.py:86-107](file:///D:/Meta%20hackathon/backend/src/claimlab/worker.py)). The status entry confirms "Retention sweeper for expired guests (T-DATA-02) is not implemented" ([docs/25](file:///D:/Meta%20hackathon/docs/25_STATUS_AND_HANDOFF.md)).
- Idempotency `response_json` copies private content (for example, selection responses include anchor quotes, [api:717-727](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)), and these records never expire (Section 2). `ToolInvocation.result_reference` keeps up to 500 chars of every tool result, including web page text ([orch:926](file:///D:/Meta%20hackathon/backend/src/claimlab/services/agent_orchestrator.py)).
- Delete during a running turn: see Section 2. Rows committed by the turn after the purge survive, for example ExperimentRun with `owner_id` and ToolInvocation results (inferred from code; the StaleDataError behaviour was verified by probe).

### Inferences
- **Restrict `read_web_page` (S):** accept only URLs that `web_search` returned this turn (normalised with `comparable_url`), and return "read only a search result" otherwise. This closes a direct injection-to-exfiltration path, such as `https://evil/?q=<passage or learner text>`. `web_search` queries remain a residual channel; bounding the query length to 400 chars already exists ([web_research.py:43](file:///D:/Meta%20hackathon/backend/src/claimlab/services/web_research.py)).
- **Filter prose links (S):** link only URLs in `web_sources` or anchors, or render unknown links as plain text plus hostname.
- **Fail closed on config (S):** default `APP_ENV` to `"production"`, or refuse to start when `SESSION_SECRET` is the default and `APP_ENV != "development"`. Also refuse sandbox runs without the dedicated venv unless `APP_ENV == "development"`.
- **Bound inputs (S):** `goal: Field(max_length=1000)`, `event_type: Literal[...]` (the known set from `ANSWER_EVENTS` + hint + message + object question), and a payload size cap (for example, 8 KB of serialised JSON) or a typed payload per event.
- **Spend cap (M):** settle `BudgetReservation` from `data["usage"]` × the configured prices, refuse new live turns when the global or per-owner budget is spent, and rate-limit guest creation per IP.
- **PDF (S/M):** bump pypdf to ≥6.x (check the `PdfReader`/`extract_text` API; these calls are basic). Separately, run extraction in a subprocess with the existing Windows Job Object or POSIX rlimit launcher from `sandbox/executor.py` and a timeout. Add a `%PDF-` magic check and return a generic parse error without exception text.
- **T-DATA-02 sweeper (M):** factor the purge out of `delete_my_data` ([api:378-429](file:///D:/Meta%20hackathon/backend/src/claimlab/api.py)) into `purge_owner(db, owner)`. Run it at startup and every N minutes (in the worker loop or a lifespan task) for owners with `expires_at < now`. Also delete expired `IdempotencyRecord`s and `BudgetReservation`s, and remove PDFs via `remove_stored_upload`. Test it with a guest whose `expires_at` is in the past.

### Gaps
- Whether muse-spark-1.3 follows injected instructions in practice. The live benchmark was not rerun, and there is no injection red-team fixture in `evaluation/benchmark.py`, which I did not read line by line.
- The exact pypdf release that fixes every known parsing DoS. I only verified the CVE-2025-55197 fix (6.0.0) from a primary-ish advisory mirror.
