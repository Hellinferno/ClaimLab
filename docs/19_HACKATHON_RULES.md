# Hackathon Rules and Project Fit

## Source and authority

This is an operational interpretation of the [participant guide supplied by Ravi](../references/PARTICIPANT_GUIDE_SUPPLIED.md) and the [public event page](https://events.cerebralvalley.ai/e/meta-ai-developer-hackathon). It is not a substitute for official rules, accepted waivers, portal requirements, or later organizer notices. The participant-only details page required sign-in during the earlier review; those later details have not been independently checked here.

## Project positioning

Recommended theme: **Push the Frontier**, on the basis of executing and investigating small technical experiments through an agentic software workflow. Recommended track: **Indie Developer**, subject to Ravi's actual team/startup status and accepted entry. Each project enters one track.

ClaimLab remains a learning product. Its concrete contribution must be real experimentation, checked outputs, semantic student interaction, and evidence-based lesson changes. Describing it as a lab does not automatically exempt it from the guide's warning about simple education chatbots/basic RAG apps. Organizer interpretation remains authoritative.

## Conditions from the supplied guide

| Condition | Implication for ClaimLab |
| --- | --- |
| Meta models must be incorporated | Real Meta inference/tool behavior must power substantive product actions |
| Public repository | Publish appropriate source and reproducible examples; exclude private data and secrets |
| Maximum four team members; solo allowed | List the actual contributors accurately |
| New work must be clear | Preserve commits, project start state, and a concise contribution account |
| Existing startup code may be extended with clear delineation | Identify pre-existing components if used; show newly built features |
| Three-minute demo video | Demonstrate actual behavior within the stated duration |
| One collaborative submission per team/startup | Appoint an actual representative and verify portal details |
| Late submissions not accepted | Use the internal buffered target |
| Rights and platform-policy compliance | Track libraries, model terms, demonstration material, and asset permissions |

The guide's discouraged examples include basic RAG, simple image analysis, simple education chatbots, medical-advice projects, job screening, nutrition/personality/sports coaching, and political/war projects. ClaimLab's defined technical-learning scope avoids adding those unrelated workflows.

## Judging

Impact 30%; use of Meta AI tooling 25%; technical depth/execution 20%; demo 25%. The guide describes baseline pass/fail review, scored review, and a final round for the top five projects per track. These describe the stated process, not a prediction of advancement.
